When building ambitious projects, execution matters far more than stubbornness. About six months ago, I made a dramatic shift: I paused the C# stack for my engine initiative, dove headfirst into **Zig**, and rebuilt everything from the ground up.

The result of that experiment was **TurianZ**—which, without false modesty, grew to become one of the most feature-rich, advanced native 3D engine projects written in Zig. Along the way, I contributed back to the ecosystem, creating tools like the most robust GUID, Markdown, and Liquid template libraries currently available in Zig.

Yet, during those same six months of deep low-level Zig development, I kept using modern **.NET / C#** for every other side project I spun up. Eventually, I realized something undeniable: **I was writing—and enjoying—significantly more C# code than Zig.**

A weekend project updating [Guinevere](https://github.com/MASS4ORG/Guinevere?utm_source=gemini) to the latest .NET features lit the spark. Revisiting the original C# **Turian** codebase sealed the deal. The code was cleaner, easier to parse, and felt remarkably natural.

After a full month of refactoring, updating, and aligning systems, I'm making it official: **The entire stack is returning home to C#.**

---

## The Elephant in the Room: Naming & Legacy

I know what you're thinking: *"Wait, Turian was C#, then it became a Zig engine, and now it’s C# again?"*

Yes. The confusion is completely justified, and people will rightfully scratch their heads. Here is how we are handling the transition cleanly:

1. **Turian (C#):** Reclaims its status as the core flagship engine and repository.
2. **TurianZ (Zig):** The Zig incarnation is now officially preserved as a legacy repository.

**TurianZ is far too valuable to abandon to the ether.** It remains one of the most capable Zig engines in existence, featuring 3D rendering, scene management, asset systems, and a fully functional editor environment. If anyone in the open-source community wants to fork, maintain, or evolve **TurianZ**, you have my full blessing and support.

## Zig vs. C#: The Engine Developer's Perspective

Spending six intense months living in Zig while keeping a foot in modern .NET gave me a unique, unvarnished look at both ecosystems.

```
       +-------------------------------------------------------+
       |                  DEVELOPMENT SPECTRUM                 |
       |                                                       |
       |   Zig                                            C#   |
       |   [Explicit / Manual]         [Reflectable / Fluent]  |
       +-------------------------------------------------------+

```

### What I Loved About Zig

* **Comptime Power:** `comptime` is genuinely miraculous. Generating structs, inspecting fields at compile time, and executing logic without runtime overhead is brilliant.


* **Zero Overhead & Predictability:** No background Garbage Collector, no runtime surprises, and absolute control over memory allocators.


* **Unrivaled C Interop:** Consuming native C libraries without glue code or header bindings remains Zig’s killer feature.



### Where Zig Struggled for This Use Case

* **Lack of Runtime Reflection & Attributes:** While `comptime` is powerful, game editors thrive on rich runtime metadata. Simulating attributes or deep object graph inspection required tedious structural workarounds.


* **No Stable ABI:** TurianZ games couldn't link against pre-compiled binaries. Because Zig lacks a stable ABI, game projects had to recompile the engine source code on *every single build*.
* **Ecosystem & Community Turbulence:** When high-profile events happen—like Bun rewriting its core from Zig to Rust, prompting viral rants from Zig leadership—it raises uncomfortable questions about ecosystem stability, developer fatigue, and long-term friction.

## The New C# Horizon: Turian & Guinevere

Reclaiming C# hasn't meant starting from scratch; it meant **upgrading everything to modern standards.** The C# codebase has already swallowed and adapted the best features born during the Zig experiment:

* **OAP (Open Asset Package):** Re-engineered for C#, bringing one of the most modern asset packaging systems to the .NET ecosystem.
* **Guinevere GUI:** Better than ever, leveraging modern .NET features for clean, immediate, and responsive UI layout.
* **Turian Studio & Gaya:** Improved decoupling in the architecture to pave the way for the **Gaya** platform and editor layer.


* **Engine Parity:** Fully modern 3D rendering pipelines, quality-of-life enhancements, and native performance optimizations.
